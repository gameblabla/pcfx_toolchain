# Appendix A — Ordering of Write PE Register Commands

The ordering between buffer switching (swap) performed by a `Write PE register (frame control register)` command and subsequent writes to other PE registers is not always guaranteed.

## A.1 Symptom

When an explicit swap command (`write PE register (frame control register: SWP)`) is followed by a `Write PE register` command that changes a clear-related register, such as the PE clear-color-value register or PE clear-Z-value register, the later register write can overtake the swap operation.

### 1. Example

```c
WritePEReg(PE_Clear_Color_Value_Reg, 0x0000);
WritePEReg(PE_Frame_Control_Reg, SWP|SWV|SWP_BUFFER);
WritePEReg(PE_Clear_Color_Value_Reg, 0xface);
```

### 2. Expected behavior

Because these operations are expected to remain ordered, the back buffer should be cleared with `0x0000`.

### 3. Actual behavior

The following PE-register write overtakes the swap operation, so the buffer is cleared with `0xface`.

## A.2 Workaround

Before any PE-register write that must not overtake a swap command, insert a dummy swap command: write the PE frame-control register without setting `SWP`.

```c
WritePEReg(PE_Clear_Color_Value_Reg, 0x0000);
WritePEReg(PE_Frame_Control_Reg, SWP|SWV|SWP_BUFFER);
WritePEReg(PE_Frame_Control_Reg, 0x0);          /* dummy swap */
WritePEReg(PE_Clear_Color_Value_Reg, 0xface);
```

## A.3 Explanation

The PE registers are referenced by both the memory controller and the PE. When the PE needs to access memory, it handshakes using the Busy signal from the memory controller. Accesses to ordinary PE registers do not observe this Busy signal; only the PE frame-control register is controlled by Busy.

When the `SWP` bit in the PE frame-control register is set, the memory controller asserts Busy and prohibits memory access. When `SWV` is also set, it waits for the next Vsync, swaps the display buffers, and then performs any requested clear operation. Busy remains asserted throughout this interval. If a clear-related register is changed while the hardware is waiting for Vsync, the clear operation after Vsync uses the changed value.

In the example above, `SWP` is set in the PE frame-control register and the PE clear-color-value register is then changed. The buffer is consequently cleared with the new value.

Because the PE frame-control register alone is governed by Busy, a dummy access to that register guarantees that subsequent PE-register writes do not take effect until the swap operation has completed.

The same technique can guarantee ordering between sprite drawing and a swap. Sprite drawing is started by writing the memory-mapped Sprite control register. Starting a sprite after issuing a swap command does not by itself guarantee execution order: sprite startup can overtake the swap because the delay before a swap actually executes is not fixed. Use the following sequence.

### 1. Issue the swap command

```c
WritePEReg(PE_Frame_Control_Reg, SWP|SWV|SWP_BUFFER);
```

### 2. Issue a dummy swap command

```c
WritePEReg(PE_Frame_Control_Reg, 0x0);
```

### 3. Issue PE sync

```c
WritePEReg(PE_Control_Reg, PES);
```

### 4. Wait for PE sync

```c
while (!(ReadMemReg(Interrupt_Status_Reg) & PES)) ;
```

### 5. Start sprite drawing

```c
WriteMemReg(Sprite_Control_Reg, SCTaddress);
```

With this sequence, execution of PE sync—the write to the PE control register—is guaranteed to occur after the buffer switch. Sprite startup therefore also occurs after the buffer switch.

# Appendix B — Hidden Clear Mode

Hidden clear mode can make the effective buffer-clear time zero. As the Video Out module reads pixel data from the front buffer, it manipulates the pixel-valid flag planes `PVLD[1..0]` in that buffer. This feature operates correctly only in 256×240 mode.

To use hidden clear, configure the related registers as follows.

## Display Control Register

```text
BCM[1..0] = 0   /* Do not perform a clear operation; see Note 1 */
DTT       = 0
ASWP      = X   /* Auto-swap mode */
HCE       = 1   /* Hidden-clear enable */
FSC[5..0] = X   /* Frame-rate setting */
```

## PE Frame-Control Register

```text
BSL[1..0] = 2   /* Swap front and back */
SWV       = 1   /* Swap with Vsync */
```

## PE Mask Register

```text
xx11 1111 1111 1111   /* Bits corresponding to PVLD[1..0] = 1 */
```

This causes `PVLD` to be set during 3D drawing.

## PE Clear-Mask Register

```text
xx11 1111 1111 1111   /* Bits corresponding to PVLD[1..0] = 1; see Note 2 */
1111 1111 1111 1111   /* When also using collision detection */
0011 1111 1111 1111   /* When also using fog/overlay */
```

## PE Clear-Color-Value Register

```text
xx00 xxxx xxxx xxxx   /* Bits corresponding to PVLD[1..0] = 0 */
0000 xxxx xxxx xxxx   /* When also using collision detection */
```

## Sprite Section

```text
SCT first word: Flag set bits [3..0] = xx11
```

This sets the `PVLD[1..0]` bits.

```text
SCT first word: Flag check mask [3..0] = xx00   /* when Cden = 1 */
```

When a sprite is used to draw a background-like image before 3D drawing, the following additional settings are required:

```text
SCT first word: set Fnc.lvl to 0 or to 2 or higher
Zcmp = 0              /* Do not compare Z; always write Zvalue */
SCT sixth word: Zvalue = 0x0000   /* Farthest value */
```

### Notes

1. If an operation is selected with `BCM[1..0]` or `DTT`, that clear operation is performed when the screen is switched. `HCE` specifies only the Video Out behavior and the Z-comparison behavior. After a screen switch, the clear operation selected by `ASWAP`, `BCM`, and `DTT` remains effective as before.
2. The values of the PE clear-mask register and PE clear-color-value register also apply during clearing by the Video Out side.
3. When the Video Out side physically clears the display-buffer contents according to the PE clear-mask and PE clear-color-value registers, it clears only the two bits `display buffer[15..14]`. Hidden clear can therefore be used at the same time as two-bit collision detection. In that case, set `PE clear color value register[15..14] = 00` and `PE clear mask register[15..14] = 11`.
4. Hidden clear mode does not operate correctly in 320×200 mode (`PE control register: WDM=1`). Use it only in 256×240 mode.
