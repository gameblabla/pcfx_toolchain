# One big textured mesh at 8bpp

The hard case of PC-FX software 3D: a single mesh of thousands of textured faces that
the user wants **kept intact**, drawn at the resolution they asked for. Everything here
is written for an arbitrary mesh; §12 records one project's measured numbers as a worked
example, and those numbers are examples, not requirements.

Start from [pcfx-3d-from-scratch] if there is no program yet. Read [pcfx-software-3d]
for whether the frame rate you were asked for is reachable at all.

**The prohibition that gives this skill its shape:** you may not buy speed by decimating
the mesh, dropping small faces, halving the raster, or reviving a different bit depth.
Those are scene changes. Propose them to the user; never perform them silently and then
report the resulting fps as an optimization.

## 1. Freeze the contract, generated from the asset

```c
/* scene_contract.h — every value generated by the asset builder */
#define MESH_VERTEX_COUNT   <from manifest>
#define MESH_FACE_COUNT     <from manifest>
#define SCREEN_W            256      /* the requested output width  */
#define SCREEN_H            240      /* the requested output height */
#define SCENE_MIN_TRIANGLE_AREA2 0   /* 0 = every projected face drawn */
```

A validator runs in the build and fails it on any regression:

```python
assert vertex_count == manifest["vertices"]
assert face_count   == manifest["faces"]
assert screen_w == REQUESTED_W and screen_h == REQUESTED_H
assert make_default("MIN_TRIANGLE_AREA2") == "0"
for banned in ("RENDER_SCALE_SHIFT", "expand_raster_2x",
               "SCENE_4BPP", "SCENE_HIGH_COLOR"):
    assert banned not in active_source
```

`MIN_TRIANGLE_AREA2 > 0` is a **profiling-only experiment**. On a dense organic mesh the
"microtriangles" it rejects are exactly the small faces forming continuous hair, cloth,
hand and face surfaces; rejecting them punches holes and breaks texture continuity while
the source asset remains numerically intact. It must never be the release default.

**Vertex count and face count are asset properties, not universal constants.** The same
authoring file yields *more* vertices once skinning is involved, because coincident bind
positions with different skin influences cannot be merged ([pcfx-character-animation]).
Take the counts from your manifest; never assert numbers copied from another project.

## 2. Presentation packing is not a resolution change

KING can read a source surface wider than the screen and step through it with an affine
transform. That lets you keep a **native-resolution software raster in main RAM** while
writing a KRAM surface whose geometry suits the upload path. It does **not** mean you are
rendering at half resolution.

```text
main-RAM software raster : SCREEN_W × SCREEN_H, one byte per logical pixel
KING source surface      : 512 × 256, 8bpp
KRAM source row          : 256 halfwords
logical pixel x          : duplicated into one KRAM halfword
KING affine A            : 0x0200  (source x step = 2.0)
KING affine D            : 0x0100  (source y step = 1.0)
displayed result         : SCREEN_W × SCREEN_H, full resolution
```

Each logical byte `p` becomes `(uint16_t)(p | (p << 8))`. KING samples source x at
0, 2, 4, …; duplicating both byte lanes makes the result independent of which byte the
affine fetch path selects.

```c
#define BG_SOURCE_W          512
#define BG_SOURCE_H          256
#define BG_ROW_WORDS         (BG_SOURCE_W / 2)                 /* 256 */
#define BG_PAGE_STRIDE_WORDS ((BG_SOURCE_W * BG_SOURCE_H) / 2)

eris_king_set_bg_size(KING_BG0, KING_BGSIZE_256, KING_BGSIZE_512,
                                KING_BGSIZE_256, KING_BGSIZE_512);
king_write_reg16(0x38, 0x0200);   /* A = 2.0    */
king_write_reg16(0x39, 0x0000);   /* B = 0      */
king_write_reg16(0x3a, 0x0000);   /* C = 0      */
king_write_reg16(0x3b, 0x0100);   /* D = 1.0    */
king_write_reg16(0x3c, 0x0000);   /* centre X   */
king_write_reg16(0x3d, 0x0000);   /* centre Y   */
```

Projection stays native:

```c
sx = (SCREEN_W / 2) + ((x * factor) >> 8);
sy = (SCREEN_H / 2) + ((y * factor) >> 8);
```

**ANTI-PATTERN.** These are the shapes that turn "affine presentation" into a silent
downscale, and each of them has been written here by a model that believed it was
optimizing:

```c
#define SCENE_RENDER_SCALE_SHIFT 1      /* NO — halves the raster            */
scene_expand_raster_2x(buf);            /* NO — a second RAM surface         */
tank_buf_draw_triangle(buf, 128, 128, 120, ...);  /* NO — 128x120 canvas     */
```

A smaller viewport can be a legitimate, *approved* design decision. It cannot be an
implicit consequence of choosing an affine surface.

## 3. Match the texture sampler to the UV domain exactly

Exporters commonly write UVs in a 0–255 domain while the atlas tiles are 64×64. The
sampler must scale, not mask:

```c
fixed_u = source_u << 6;
texel_u = (fixed_u & 0x3f00) >> 8;      /* runtime form   */
texel_u = (source_u >> 2) & 63;          /* equivalent, host/reference form */
```

`uv & 63` repeats each tile four times per axis. The output looks like a corrupted asset,
and the usual next move — blaming the mesh — is wrong. Add a host regression test
asserting the two expressions agree over a broad **signed** range.

Repack tiles at boot into lanes of a single wide row so a face's texture base is an add:

```c
for (int lane = 0; lane < TILE_LANES; ++lane)
    for (int y = 0; y < TILE_H; ++y)
        memcpy(runtime + y * ATLAS_ROW + lane * TILE_W,
               source_tile[lane] + y * TILE_W, TILE_W);

texture_base       = runtime + lane * TILE_W;
texture_row_stride = ATLAS_ROW;
```

Verify every repacked texel by lane, row and column in a host test. Any preview or
reference renderer must use the identical mapping and the release default
`MIN_TRIANGLE_AREA2 = 0`, or its images cannot be used as a comparison baseline.

## 4. Cull → sort → expand: one compact stream, not two fat ones

**ANTI-PATTERN** (two full-width record copies per face, per frame):

```text
source face -> 28-byte unsorted draw record -> depth sort
            -> second 28-byte sorted record -> rasterizer
```

**Do this instead:**

```text
source face -> 4-byte {depth, source_index} key when accepted
            -> radix sort compact keys
            -> expand each accepted face ONCE, in painter order
            -> enter the rasterizer once for the whole batch
```

```c
typedef struct {
    int16_t  depth;
    uint16_t source_index;
} SceneFaceKey;
_Static_assert(sizeof(SceneFaceKey) == 4, "one sequential word");
```

Keep depth and index **interleaved in one array**. Two parallel arrays alternate between
2 KiB DRAM pages on every element and cost more than the bytes they save.

Emit pre-scaled byte offsets offline so the runtime addresses a projected vertex with a
single add:

```python
PROJECTED_VERTEX_STRIDE = 8
face_offsets = [i * PROJECTED_VERTEX_STRIDE for i in face_indices]
assert max(face_offsets) <= 0xffff      # else widen the field
```

```c
const SceneProjectedVertex *v =
    (const SceneProjectedVertex *)((const uint8_t *)projected + face->projected_offset[k]);
```

Then expand and draw as a batch — **never cross the C/assembly boundary per triangle**:

```c
scene_expand_scheduled_faces_v810(order, count, static_faces, projected);
scene_draw_faces_v810(g_faces, count);
```

## 5. V810 kernels, and the immediate-width trap

ABI used throughout this workspace:

```text
r6-r9    arguments
r6-r19   caller-saved
r20-r29  callee-saved   (save every one you modify)
r30      high half of MUL
r31/lp   link pointer
```

### The trap that produces a faster, corrupted render

V810 `ADD imm5,reg` takes a **signed 5-bit** immediate: range **−16..15**. GNU `as`
accepts a larger constant and truncates it *without an error*. In a real face loop here,
`add 24,r20` assembled as `add -8,r20`, walked backwards through the face records,
submitted a fraction of the geometry, and produced a deceptively *faster* run with most
of the mesh missing. Use the three-operand form for any larger stride:

```asm
    addi    24,r20,r20          /* correct record advance */
```

Disassemble every hand-written kernel, and add a source audit that rejects immediate
`ADD` operands outside −16..15. When a change makes the renderer faster, independently
recompute the front-facing face count at a fixed orientation and check it against the
number actually submitted.

### Cull kernel shape

Per face, sequentially: read the immutable record; add its three pre-scaled offsets to
the projected base; compute the screen-space signed double area; reject backfaces (and
microtriangles only if the experiment knob is on); compute mean depth; write one
sequential 4-byte key.

```asm
    ld.h    0[r20],r10
    ld.h    2[r20],r11
    ld.h    4[r20],r12
    andi    65535,r10,r10
    andi    65535,r11,r11
    andi    65535,r12,r12

    mov     r21,r26
    add     r10,r26
    mov     r21,r27
    add     r11,r27
    mov     r21,r28
    add     r12,r28

    ld.h    0[r26],r13       /* x0 */
    ld.h    2[r26],r14       /* y0 */
    ld.h    0[r27],r15       /* x1 */
    ld.h    2[r27],r16       /* y1 */
    ld.h    0[r28],r17       /* x2 */
    ld.h    2[r28],r18       /* y2 */

    sub     r13,r15
    sub     r14,r18
    mul     r18,r15
    sub     r14,r16
    sub     r13,r17
    mul     r17,r16
    sub     r16,r15
#if SCENE_MIN_TRIANGLE_AREA2 > 0
    movea   SCENE_MIN_TRIANGLE_AREA2,r0,r10
    cmp     r10,r15
#else
    cmp     0,r15
#endif
    ble     .Lskip
```

Note there is no divide and no float anywhere in the kernel, and the three vertex loads
are grouped per vertex so each pair shares an open DRAM page.

## 6. Native raster rules

All clipping and dirty bounds use the contract dimensions directly, with unsigned
compares for the double bound:

```c
if ((unsigned)v0->y >= SCREEN_H ||
    (unsigned)v1->y >= SCREEN_H ||
    (unsigned)v2->y >= SCREEN_H) reject;

scene_draw_triangle(buffer, /*stride*/ SCREEN_W, SCREEN_W, SCREEN_H, 0, 0, face);
```

The physical stride equals `SCREEN_W` bytes and there is no expansion stage. An outline
width of two means exactly two output pixels.

## 7. Upload only what changed

Keep the main-RAM raster and one shadow per KRAM page, both compact:

```c
uint8_t raster[SCREEN_W * SCREEN_H];
uint8_t shadow[BUFFER_COUNT][SCREEN_W * SCREEN_H];
```

Do **not** allocate a 512-wide expanded RAM framebuffer. Expansion happens at the output
port, one byte at a time, for changed bytes only.

Address geometry for row `y`:

```text
source byte offset       = y * SCREEN_W
shadow byte offset       = y * SCREEN_W
affine KRAM word offset  = y * BG_ROW_WORDS      (512-wide surface)
linear KRAM word offset  = y * (SCREEN_W / 2)    (fallback surface)
```

One source dword maps to **2** KRAM words linear, **4** words affine. Copying the
two-word advance from a linear uploader into the affine one is a standard bug; the host
model in §7.2 catches it.

### 7.1 Compare with DRAM pages in mind

The raster and each shadow are separate arrays tens of KiB apart. Alternating one dword
from each reopens a different 2 KiB page on **every** load. Cluster four from each:

```asm
    ld.w    0[r20],r15
    ld.w    4[r20],r16
    ld.w    8[r20],r17
    ld.w    12[r20],r18
    ld.w    0[r21],r26
    ld.w    4[r21],r27
    ld.w    8[r21],r8
    ld.w    12[r21],r9
```

All four equal → advance both pointers and the KRAM offset without touching KING. Any
differ → process the four scalar, preserving run state. Seek KING only where a changed
run *starts*; sequential words then stream through the data register.

Byte duplication for the affine surface:

```asm
    mov     r10,r12
    andi    255,r12,r12
    mov     r12,r13
    shl     8,r13
    or      r13,r12
    out.h   r12,0x604[r0]
    /* repeat for shifts 8, 16, 24 */
```

Use 16-bit KRAM writes. Do not replace four `out.h` with `out.w` without measuring —
32-bit I/O batching measured slower and less reliable in earlier work here.

### 7.2 Host-model the address mapping before you need a target

```python
assert SCREEN_W * SCREEN_H == EXPECTED_RASTER_BYTES
assert BG_SOURCE_W * BG_SOURCE_H // 2 == EXPECTED_SURFACE_WORDS
assert BUFFER_COUNT * EXPECTED_SURFACE_WORDS <= KRAM_WORDS_AVAILABLE
assert duplicate_byte(p) == p * 0x101

kram_word = y * BG_ROW_WORDS + x            # a changed dword writes 4 words
for lane in range(4):
    kram[kram_word + lane] = duplicate_byte(src[y * SCREEN_W + x + lane])
```

Initialise the modelled surface from the old shadow, apply randomised changed dwords
**including the first and last column and row**, and assert the affine-visible bytes
match the new raster. This catches wrong row strides, two-word advances, and byte-order
mistakes. It does not replace running on the target.

### 7.3 Correct source, wrong motion → suspect the artifacts

If the object orbits the world origin although the checked-in transform centres it on
its own origin, **do not** rewrite the geometry first. A committed `.bin`/`.cue` is
executable input, not a cache the emulator regenerates.

1. Confirm the source centres the mesh and applies camera distance separately.
2. Read the project's build wrapper before guessing its make target.
3. Rebuild the **disc**, not an object file, e.g. `./build_with_toolchain.sh "$V810_GCC" clean all`
   — such a wrapper puts the V810 tools on `PATH`, runs the project makefile, then
   `bincat` and `pcfx-cdlink` to regenerate the image and `.cue`.
4. Screenshot past BIOS boot (≥1800 fields), sampling several animation phases.
5. `git status`, and commit every regenerated artifact with the source fix. Never leave a
   stale boot image beside corrected source.

**ANTI-PATTERN:** editing centring, camera or rotation code because the display looks
orbital. That introduces a compensating error while the emulator still boots the old disc.

## 8. Outlines from the finished image, not from more geometry

Generate the outline as an image operation on the completed 8bpp raster:

1. classify non-background bytes into a silhouette mask;
2. dilate horizontally;
3. dilate vertically;
4. paint `dilated & ~model` with the black palette index.

Keep the horizontal and vertical passes as **separate** routines and align hot sections
to 1 KiB where the linker honours it — a combined routine can conflict with itself in the
direct-mapped icache. Do not redraw thousands of inflated triangles.

Consider a second 2bpp KING layer for the outline only when *all* hold: the measured
outline stage exceeds roughly 5–10% of frame time; a silhouette mask already exists
without another geometry pass; transparency and layer order are verified; the mask upload
plus KING setup costs less than the current writes; and it does not reintroduce a
discarded renderer. Bytes per pixel alone is not evidence of a speedup.

## 9. Icache and DRAM discipline

Keep projection, cull, expansion, raster batch, outline-H, outline-V and KRAM upload as
**separate compact routines**, and measure misses per symbol. The icache is 1 KiB and
direct-mapped: a hot loop that does not fit evicts itself every iteration, and two hot
functions colliding modulo 1 KiB evict each other.

Favour: sequential packed keys; sorted index streams; contiguous final draw records;
grouped source reads then grouped shadow reads; output-port expansion instead of a second
RAM surface.

A lower instruction count can still lose if it increases DRAM-page alternation or icache
refills. Let the profiler decide ([pcfx-v810-profiling]).

## 10. Freestanding runtime gate

If the release contract forbids newlib, float, 64-bit arithmetic, software divide
helpers, timer IRQs and registered handlers, read [pcfx-freestanding-runtime] before
building, and satisfy all of:

```text
- no float/double/int64_t/uint64_t/long long in the target sources
- no libc memory, allocation, formatting or exit calls
- reciprocal/trig tables generated offline and compiled const
- variable 32-bit division is explicit V810 DIV/DIVU with r30 clobbered
- no timer API, irq_set_handler, or interrupt-attributed function
- Makefile is freestanding and uses -mno-prolog-function
- release link omits -lc, -lsim and -lgcc
- final map/ELF audit rejects forbidden archives and helper symbols
```

A source grep is not proof — GCC synthesizes block-copy and arithmetic libcalls. The
clean link plus map/symbol audit is the acceptance gate. If the toolchain or profiler is
unavailable, report FPS, DRAM penalties and icache misses as `unavailable`; never promote
an estimate into a metric.

## 11. The finite-state output stream (when it is legal)

After ordinary geometry and raster work, ask whether the **visible state set is finite and
enumerable**. If the animation advances a fixed step through a closed cycle, e.g.

```c
angle = (angle + STEP) & 255;      /* -> 256/STEP distinct poses */
```

with fixed camera, lighting, texture, palette, background and projection, then the
strongest legal optimization is to cache the renderer's **exact native output** rather
than approximate the geometry.

**This is invalid** — use [pcfx-character-animation] instead — the moment any of these
exist: a selectable animation library, world-space movement, user zoom, a moving camera,
skeletal deformation, or clips that may be added later.

### Prove equivalence, then encode

1. Build the last graphics-correct full-geometry renderer.
2. Capture the finished raster (after rasterization *and* outline) for every state.
3. Capture by presented-frame counter changes, never by host wall clock.
4. Store the state key beside each `SCREEN_W * SCREEN_H`-byte indexed frame.
5. Require every expected state exactly once.
6. Compare the optimized release against the baseline at every state, **byte for byte**.

A screenshot comparison is insufficient — compare the indexed BG0 bytes so palette,
outline, stale-pixel erasure and every microtriangle are covered.

Do not store the states uncompressed. For each target state and each row: take the union
of the previous state's non-background range and the target's, align the start down and
the end up to four bytes, and store the **final target bytes** for that aligned union.
Including the previous range erases stale silhouette pixels; storing exact target
background bytes removes the need for a separate clear. Keep each command inside one
raster row so destination writes stay sequential.

```text
32-bit header
  bits  0..15 : aligned destination byte offset in the raster
  bits 16..23 : payload word count minus one
  destination 0xffff : end of state
followed by aligned 32-bit payload words
```

Decoder — one small sequential word-copy loop, freestanding, far below 1 KiB:

```asm
_scene_apply_prebaked_state_v810:
    movhi   1,r0,r13
    addi    -1,r13,r13          /* 0x0000ffff terminator */
.command:
    ld.w    0[r6],r10
    addi    4,r6,r6
    mov     r10,r11
    andi    0xffff,r11,r11
    cmp     r13,r11
    be      .done
    shr     16,r10
    andi    0xff,r10,r10
    addi    1,r10,r10
    add     r7,r11
.copy:
    ld.w    0[r6],r12
    st.w    r12,0[r11]
    addi    4,r6,r6
    addi    4,r11,r11
    addi    -1,r10,r10
    bnz     .copy
    br      .command
.done:
    jmp     [lp]
```

Acceptance is not "it is fast":

```text
[ ] finite visible-state set is proven, not assumed
[ ] every state captured from a graphics-correct baseline
[ ] native dimensions and 8bpp indices unchanged
[ ] outline bytes included
[ ] all states compare byte-for-byte
[ ] original asset and a geometry-path build flag remain available
[ ] profiler runs traverse the complete state cycle
```

## 12. Worked example (one project's measured numbers)

These are **an example of what the procedure produced once**, not constants to assert in
a different project.

```text
asset            5,563 vertices / 10,628 faces (static rigid version)
                 6,246 vertices / 11,508 faces (skinned version — influence seams)
raster           256 x 240, 8bpp, outline width 2
states           128 poses, angle += 2 over 8 bits
```

| Path | Presented FPS | DRAM penalty/field | I-cache misses/field |
|---|---:|---:|---:|
| Corrected full geometry | 3.017 | 46,447 | 4,502 |
| Opaque write-once geometry raster | 4.100 | 37,071 | 928 |
| Exact native state stream | **30.117** | **23,996** | **132** |

The last path removes repeated transform, cull, sort, triangle setup, texture sampling,
overdraw and outline dilation, keeping a small sequential decoder plus the delta uploader:
DRAM penalties −48.3%, icache misses −97.1%. All 128 61,440-byte poses matched the
full-geometry baseline byte-for-byte; the encoded stream was 1,152,152 bytes — that is
rendering *output*, and the original asset and a `PREBAKED_POSES=0` geometry build were
both retained.

A rejected 5.017 FPS capture from the same project is the cautionary result: it came from
the truncated `add 24` stride of §5 and omitted most of the geometry. Correctness gates
precede performance publication.

## 13. Build matrix and reporting

Always clean between A/B builds; stale objects keep old flags.

```bash
make clean all LINEAR_BG=0 OUTLINE=1 OUTLINE_WIDTH=2 MIN_TRIANGLE_AREA2=0   # release
make clean all LINEAR_BG=0 OUTLINE=1 OUTLINE_WIDTH=2 MIN_TRIANGLE_AREA2=4   # experiment only
make clean all LINEAR_BG=0 OUTLINE=0 MIN_TRIANGLE_AREA2=0                   # outline cost
make clean all LINEAR_BG=1 OUTLINE=1 MIN_TRIANGLE_AREA2=0                   # presentation A/B
make clean all LINEAR_BG=0 OUTLINE=1 MIN_TRIANGLE_AREA2=0 PROFILE_STAGES=1  # stage counters
```

Record for every run: presented FPS and fields per rendered frame; cycles/field and CPI;
per-stage cycles; DRAM data-page penalties; per-symbol icache misses; changed vs unchanged
uploader blocks; accepted vs culled faces; fixed-orientation screenshots or framebuffer
hashes; and the UV/atlas regression results.

The meaningful presentation A/B is **affine vs linear at the same native raster**. Comparing
an affine full-resolution build against a lower-resolution renderer and attributing the
difference to presentation mode is not a measurement.

FPS must come from the delta of a presented-frame counter over profiler video fields —
not the HUD, not CPU utilization, not host wall clock. Start both captures from the same
warmed savestate; treat a missing profiler block, a missing RAM dump, a zero warm counter,
a stale ELF, or a >3% spread between repeats as a **failed measurement**. Report
unavailable values as null, never zero. See [pcfx-self-improve] §7.

### Checklist

```text
[ ] Preserve the manifest's vertex and face counts.
[ ] Keep software raster and visible output at the requested dimensions.
[ ] Treat a wider KING surface as affine storage, not half-resolution output.
[ ] Reject RENDER_SCALE_SHIFT and 2x expansion code.
[ ] Default MIN_TRIANGLE_AREA2 to 0; nonzero is profiling-only.
[ ] Scale UVs to the tile size ((uv >> 2) & 63 for 0-255 UVs into 64x64 tiles).
[ ] Verify the runtime atlas lane/row/column repack in a host test.
[ ] Cull to packed 4-byte keys; expand accepted faces once.
[ ] Reject V810 immediate ADD operands outside -16..15; use ADDI.
[ ] At a fixed orientation, recompute front-facing count and match submitted faces.
[ ] Generate projected byte offsets offline.
[ ] Batch-enter V810 rasterization; never per triangle.
[ ] Expand bytes only at the KRAM output port.
[ ] Keep the outline at native resolution; baked states must include its bytes.
[ ] For a finite state set, validate every state buffer byte-for-byte first.
[ ] Keep the source asset and a geometry-path build available.
[ ] Compute FPS from presented-frame deltas; two runs; 3% gate.
[ ] Inspect DRAM penalties and per-symbol icache misses.
[ ] Commit code and skill discoveries separately.
[ ] Never report a predicted FPS as measured.
```
